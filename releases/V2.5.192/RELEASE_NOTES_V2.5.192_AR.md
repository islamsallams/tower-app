# إصدار V2.5.192 — اعتماد التسوية والتراجع والدفعات

- شاشة اعتماد واحدة بتوزيع واضح: المشتريات وأتعاب المشاوير والدفعات/الرصيد السابق، وحقلان اختياريان «أتعاب إضافية» و«المدفوع الآن»، ثم إجمالي الحساب والمطلوب نقدًا والرصيد الدائن بعد التسوية. الأرقام تتحدث أثناء الكتابة، والمبالغ المعروضة تتقرب لأعلى بينما حسابات القروش محفوظة.
- مثال180 ومدفوع200 ينتج رصيد20؛ إضافة أتعاب10 تجعل الإجمالي190 والرصيد10. رصيد سابق220 وإجمالي190 ومدفوع إضافي50 ينتج رصيد80 والمطلوب نقدًا صفر.
- المدفوع الفارغ يحتفظ بالسلوك السابق: تسجيل سداد المطلوب فقط. لو السابق يغطي الحساب لا تنشأ دفعة نقدية جديدة. صفر صريح مسموح عند كفاية السابق. يمكن إضافة مدفوع جديد حتى لو المطلوب النقدي صفر.
- المدفوع الأقل من المطلوب يظهر الإجراء «تسجيل دفعة» بوضوح؛ تسجل الدفعة الفعلية وحدها، وتبقى المشاوير مفتوحة. الأتعاب الإضافية تظل مقترحًا ولا تُسجل قبل تسوية مكتملة. المدفوع صفر مع وجود مطلوب لا ينشئ دفعة صفرية ولا يعتمد تسوية ناقصة.
- الأتعاب الإضافية بند مستقل للتسوية، لا تُلحق بمشوار عشوائي. التفاصيل والنسخ والمشاركة والطباعة/PDF تستخدم نفس بيانات المبلغ السابق والمدفوع الآن والأتعاب الإضافية، بما في ذلك عرض التفاصيل الحالي عند الحارس دون تغيير دوره أو اختيار السجلات المتاحة له.
- الحفظ معاملة واحدة: المدفوع والتسوية والمشاوير والدفعات والترحيل وسجل العملية معًا أو لا شيء. مرجع ثابت يمنع تكرار الدفع عند إعادة المحاولة؛ تغيير الحساب بعد المعاينة يتطلب مراجعة جديدة. لا إعادة حفظ تلقائية. زر الحفظ محمي من التكرار ولا يمكن إغلاق نموذج جارٍ حفظه.
- إزالة شرط منع التراجع بسبب مشاوير أحدث وفق طلب المستخدم. يعيد التراجع مشاوير التسوية ودفعاتها الأصلية، ويحافظ على المشاوير والدفعات المستقلة التي أضيفت بعدها.
- المدفوع الفعلي المكتوب أثناء التسوية يرجع دفعة مفتوحة. دفعة الإقفال التلقائية القديمة تتعكس كما كانت، والترحيل الناتج عن التسوية يُلغى؛ الأتعاب الإضافية الملغاة لا تنتقل إلى المشاوير المفتوحة. لا يُنشأ سداد أو رد نقدي افتراضي أثناء التراجع.
- قاعدة آخر تسوية واحدة فقط باقية دون تخطي الملغاة، وكذلك منع التراجع إن استُخدم رصيدها المرحل. التراجع معاملة كاملة أيضًا؛ أي فشل يُرجع كل التغييرات. تعمل هذه القاعدة على التسويات القديمة والجديدة، ولا تُحوّل الأرصدة التاريخية.
- التسوية الملغاة تبقى ظاهرة وقابلة للفتح، مع وصف «ملغاة» ومبلغ أحمر وتوضيح أن تفاصيلها سجل تاريخي. إشعار اعتمادها الموجود يتحدث إلى إشعار إلغاء بدل تركه يوحي بأنها ما زالت معتمدة؛ لا يُنشأ إشعار إضافي للتجربة.
- دفعات تحت الحساب كروت واضحة بمبلغ أخضر ومصدر مفهوم وتاريخ/وقت، والكارت يفتح التفاصيل. المعرف التقني داخل التفاصيل فقط. إلغاء الدفعة داخل التفاصيل بنفس شروط الخادم الأصلية (دفعة ساكن مفتوحة وغير مرتبطة بتسوية)، ولا يُتاح إلغاء الرصيد المشتق كدفعة مستقلة.
- تنبيهات التطبيق منظمة باتجاه RTL وخط النظام وأيقونة وعنوان ونص وأزرار منفصلة. أسماء الدوال والمراجع الفنية داخل التفاصيل المنسوخة؛ النسخ وعرض التفاصيل والإغلاق باقون. القيود المعروفة تظهر كتنبيه أصفر، والفشل التقني بالأحمر. لا تغيير لعمليات باقي الصفحات بسبب تغيير شكل الرسالة.
- تسجيل المشاوير وتعديلها وإلغاؤها والمسافات والتنبيهات الملونة وصلاحياتها وحسابات الوحدة والخدمات والمهمات لا تتغير في هذه الدفعة.

## التثبيت

شغّل SQL244 الجديد المرفق مرة واحدة ثم ارفع ZIP التشغيل V2.5.192 بعد نجاحه. لا تعِد تشغيل أي SQL قديم. احتفظ بـSOURCE للتطوير.

## التحقق

اختبارات محلية للكود وSQL والـWorker فقط. لا متصفح أو شاشات أو PDF مولّد أو GUI أو أونلاين أو كتابة مالية حقيقية أو نشر Cloudflare. قبول الشاشة والتشغيل الأونلاين للمستخدم.
