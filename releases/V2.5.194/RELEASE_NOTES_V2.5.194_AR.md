# إصدار V2.5.194 — إلغاء مدفوع الاعتماد عند التراجع

- مدفوع «المدفوع الآن» المسجل ضمن اعتماد تسوية كاملة يلغى مع التراجع عنها، مثل مدفوع الإقفال التلقائي، بدل رجوعه دفعة مفتوحة. قاعدة192 المخالفة مستبدلة بتوجيه المستخدم الجديد.
- يحفظ رقم الدفعة داخل بيانات التسوية، فلا يختار الإلغاء دفعة مستقلة لمجرد تطابق المبلغ. التسويات القديمة ذات المدفوع الصريح تحتاج إثباتًا من لقطة الدفعة وطلب الحفظ وهوية المنفذ وتوقيت إنشاء التسوية. عند فقد الدليل أو الغموض لا يجري التراجع أو يغير أي جزء من الحساب.
- الدفعات المستقلة والدفعات الجزئية التي لم تنشئ تسوية والرصيد السابق تعود للحساب. المشاوير الأحدث والدفعات المستقلة الأحدث محفوظة. الإضافة الملغاة لا تنتقل للمفتوحة، والترحيل المشتق يلغى.
- SQL246 يتضمن معالجة محددة فقط لمدفوع200 في التسوية الملغية رقم3 للوحدة26، بعد إثبات الارتباط. يرفض التثبيت والمعالجة معًا إذا تغيرت الحالة أو استُخدمت الدفعة في تسوية فعالة. لا تصحيح تلقائي لباقي الوحدات أو التسويات.
- الإلغاء يحفظ الدفعة وتفاصيلها التاريخية ولا يحذفها، ويضيف سجل صيانة مستقل دون نسبته خطأً إلى مستخدم. إعادة تشغيل نفس التحديث لا تكرر الإلغاء أو سجل الصيانة.
- لا تعديل لمبالغ التسويات الملغية التاريخية: التسوية التي كانت تشمل المدفوع قبل التصحيح تظل تعرض أرقام اعتمادها الأصلية. الحساب المفتوح وحده يستبعد المدفوع الملغى.
- دالة tower_trip_account القديمة والإنشاء/التعديل والمسافات والتنبيهات والصلاحيات كما هي. قاعدة آخر تسوية واحدة ومنع التراجع بعد استخدام رصيدها المرحل باقيتان. صفحات ومكونات وأزرار المشاوير دون تغيير؛ الواجهة إصدار فقط، والخادم إصدار ورسالتان عربيتان جديدتان فقط.

## التثبيت

شغّل SQL246 الجديد، ثم ارفع ZIP التشغيل V2.5.194. احتفظ بـSOURCE للتطوير. ملف SQL مستقل ولا يعمل برفع ZIP.

## التحقق

نجحت فحوص SQL بقاعدة مصطنعة معزولة ونماذج الكود ومسارات الخادم وتحضير الحزم. لم يتم تشغيل SQL على قاعدة المستخدم أو رفع التطبيق إلى Cloudflare أو اختبار أي شاشة أو أونلاين. رقم525 هو نتيجة السيناريو المعروف؛ أي نشاط مستقل أحدث يؤثر على الرصيد الحالي بشكل طبيعي.
