# إصدار V3.0.1 — إصلاح تجمّد الإعدادات

- إصلاح حلقة تحديث واجهة ظهرت في V3.0.0: رسام حالة الطلبات كان يعيد تعيين textContent حتى للنص نفسه. مراقب DOM يستقبل childList ويستدعي الرسام مجددًا؛ تتراكم أعمال microtasks فتتوقف الصفحة عن الاستجابة ويظل تحميل الإعدادات معلقًا.
- مقارنة النص قبل تعيينه، ومقارنة حالة النقطة وبيان عدد الطلبات قبل تعديل class أو data-pending-count. تحديث نفس الحالة يصبح بلا أي كتابة للواجهة، والتحديث الفعلي عند تغير العدد أو حدوث خطأ يظل يعمل.
- لم يُعطّل مراقب DOM أو متابعة الكروت الجديدة. لم تتغير مصادر الطلبات أو صلاحياتها أو طريقة معالجتها، ولا الحسابات أو المشاوير أو التسويات أو التصميم أو حركة الهيدر. Worker وإشارات الإصدار فقط خارج دالة الرسام.
- فحص انحدار جديد يعيد إنتاج الحلقة على نسخة دالة V3.0.0 المجمدة، ويثبت أن النسخة المصححة تستقر عند التحميل والنجاح والخطأ وتغيّر العدد وإزالة آخر نقطة، حتى مع متابعة تغييرات الخصائص.

## التثبيت

ارفع Tower_App_V3.0.1.zip فقط. لا SQL جديد ولا إعادة تشغيل SQL251. احتفظ بالمصدر منفصلًا؛ المصدر يحتفظ بجميع ملفات V3.0.0 والأرشيف التاريخي.

بعد الرفع أغلق التبويب المعلق وافتح الموقع مجددًا، واستخدم Ctrl+Shift+R لتحميل الملفات الجديدة. لا حاجة لمسح بيانات الموقع أو الحسابات.

فحوص الكود المحلية لا تعني اختبار الشاشات أو التثبيت أونلاين؛ تجربة الواجهة على المستخدم دائمًا. لم ينفذ المساعد نشرًا على النظام الحي.
