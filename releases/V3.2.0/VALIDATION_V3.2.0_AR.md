# فحوص الإصدار V3.2.0

- عشرة فحوص نموذج الهوية: التبويبات والمدخلات والمسودة والمواضع والتكرار ولوحة المفاتيح والصحة، وفصل الشاشة والجهاز والترتيب، والخطوط والـFade والاستعادة دون حفظ.
- سبعة فحوص بنية DOM بنموذج Node عبر linkedom، دون متصفح أو CSS rendering أو صور: حصر معالجات الفحص والتصفير، دمج الأقسام وعدم تكرارIDs، مسار الحساب الشخصي، أدوات الأعضاء وصفحاتهم، الوحدات وفلاترها، طلبات الرئيسية، واستدعاء الحفظ الفعلي مع عودة نفس التبويب والشاشة والجهاز.
- سبعة فحوص SQL252 في PGlite محلي بجدول إعدادات وخطوط بديلين ووظائف التفويض القديمة: حفظ موحد، rollback عند رفض الخطوط، رفض الأنواع، حفظ جزئي لإعدادات الأمان دون مساس بالخطوط والـFade، الأذونات وإعادة التثبيت. ليست تجربة على مخطط المستخدم الحي.
- ستة Worker ببدائل HTTP: توجيه الحفظ إلى252 وتمرير الحمولة والجلسة، قراءة الـFade، وصلاحيات الإدارة والدخول والطلبات. خمسة انحدار للمراقب تعيد إنتاج حلقة300 وتثبت استقرار الحالة الجديدة؛ سبعة للطلبات، وستة للتصدير، وستة للكروت، وخمسة لحركة الهيدر.
- أربعة فحوص حفظ النطاق: محرك التسوية والمشاوير مطابق بعد استثناء تعليقات الإصدار، مداخل الأمين والمشاوير محفوظة، SQLالقديم مطابق، وQAالتاريخي ومسارات المصدر السابق محفوظة. CSSقديم محفوظ ككتلة سابقة للقواعد الجديدة. فحص صياغة app.js وworker.js.
- سبعة فحوص تحضير حزمة Updater دون رفع. CRCوتطابق public والجذر والمصدر. السكربتات المتخصصة تستعمل TOWER_PGLITE_MODULE وTOWER_DOM_MODULE لمسارات الاعتماديات المحلية؛ الاعتماديات لا تُضم إلى ZIPالتشغيل.
- لا متصفح أو Playwright أو screenshots أو توليد PDF أو كتابة مالية أو نشر حي أو إرسال Telegram أو SQLعلى الخادم. القبول البصري والأونلاين للمستخدم؛ البنود المؤجلة السابقة محفوظة.
