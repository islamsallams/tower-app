# إصدار Tower App V3.6.1

تصحيح تحميل المالية وتنظيم نماذج الوحدات ودليل الألوان. **لا يوجد SQL جديد؛ ارفع ZIP V3.6.1 فقط بالـUpdater.** لا تعِد تشغيل ملفات SQL السابقة.

## إصلاح المالية

مسار getFinanceContext في V3.6.0 ضم جدول حالات الوحدات مباشرةً. الجدول محمي دون منح SELECT مباشر؛ تجاوز RLS لا يتجاوز صلاحية الجدول، ولذلك يمكن أن ترجع القراءة42501 وتظهر رسالة صلاحيات للاتحاد على الرئيسية والمالية.

التصحيح يقرأ الحالات بالدالة المحمية المثبتة tower_unit_states_262، بنفس جلسة المستخدم، ويضم النتائج داخل Worker إلى بيانات الوحدات. لا تعديل لدور الاتحاد أو منح صلاحيات جديدة. تبقى قراءة السياق المالي من محركها الأصلي، ولا تتغير الأرصدة والقيود والحسابات. إذا كانت الحالة أو قيمة الإعفاء غير متاحة تُرفض القراءة بوضوح؛ لا تُعامل المعفاة كوحدة مطالبة بالدفع.

## الهوية والألوان

- مربع اختيار اللون وكود HEX في صف واحد، مع تصحيح أولوية CSS التي كانت تجعل حاويتهما تعرض كسطرين. يشمل نوع الوحدة وحالتها.
- نماذج إضافة وتعديل الوحدة والنوع والحالة بنفس الهوية والمسافات والخطوط وأزرار حفظ/إلغاء. حقل وزن النوع بكامل الصف، وتعطيل/تفعيل النوع إجراء ثانوي واضح باقٍ.
- حذف جملة Master Data، واختصار مدير الوحدة وشرح نقله إلى ملاحظة صغيرة. إدارة الأعضاء زر بأيقونة، يفتح فوق النموذج ويحفظ مسودته عند الرجوع؛ نقل الإدارة ما زال يحتاج المراجعة والتأكيد الأصليين.
- في قسم دليل الألوان مجموعتان: ألوان الحالات وألوان الأنواع، بالنقطة الملونة والاسم المسجل. تتجدد مع إعادة رسم القائمة بعد الحفظ، وتلتف على الموبايل. النوع المعطل مبيّن كنص أيضًا.

التوجيه المستمر المعتمد: كل شاشة يطلب المستخدم تعديلها تُوحّد تلقائيًا مع الهوية الجديدة دون طلب منفصل. **التقارير وPDF مستثناة وبدون تعديل**؛ فُحص تطابق86دالة خاصة بها.

اختبارات الكود والصلاحيات محلية فقط. لم يشغّل المساعد متصفحًا أو اختبارات شاشة أو SQL على الخادم، ولم ينشر Cloudflare أو ينفذ حذفًا/استعادة أو إرسالًا. قبول المظهر والموبايل والتشغيل الحقيقي للمستخدم. التصفير والاستعادة الفعلية ما زالا متوقفين كما كانا.
