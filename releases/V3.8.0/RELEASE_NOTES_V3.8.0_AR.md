# إصدار Tower App V3.8.0

استعادة فعلية للنسخ المشفّرة، بثلاث خطوات وبنفس هوية شاشات المهمات والإعدادات. التشفير وكلمة المرور محفوظان وفق آخر اختيارك. التصفير التشغيلي للدفعة التالية؛ غير مفعّل هنا.

## التثبيت

1. افتح Supabase ثم SQL Editor، والصق محتوى **SQL265_ATOMIC_RESTORE_V3.8.0.sql** وشغّله. هذا الملف الجديد فقط؛ لا حاجة لإعادة الملفات القديمة.
2. ارفع **Tower_App_V3.8.0.zip** بالـUpdater كالمعتاد. ملف SOURCE للحفظ والتطوير.
3. من حساب الأدمن افتح الإعدادات ← نسخ البيانات والاستعادة ← استعادة نسخة بيانات.

تشغيل SQL265 يثبت الدوال وجدول مراجعات خاصًا فقط؛ لا يستعيد أو يحذف بيانات التطبيق. رفع ZIP لا يشغّل SQL ولا يبدأ استعادة.

## الاستخدام

- اختر ملف `.towerbackup` وأدخل كلمة مروره. يُفك التشفير على جهازك، وتُمسح كلمة المرور من الحقل قبل إرسال البيانات للمراجعة.
- المراجعة تختبر إدخال البيانات وقيود الصفوف والعلاقات داخل معاملة يتم إلغاؤها، وتعرض التاريخ وأعداد الوحدات والحسابات والسجلات وتفاصيل الجداول. ليست مجرد مطابقة أعمدة.
- انتقل لنسخة الأمان: تُحمّل نسخة من البيانات الحالية مشفّرة **بنفس كلمة مرور الملف المختار**. تأكد بنفسك أن الملف محفوظ، ثم علّم التأكيد واكتب «استعادة» واضغط التنفيذ.
- المراجعة مرتبطة بالأدمن والملف وبنية القاعدة والبيانات الحالية وصالحة20دقيقة. تغيير بيانات العمل يتطلب مراجعة ونسخة أمان جديدتين.
- التنفيذ معاملة واحدة: إما نجاح كامل أو تراجع كامل. القيود المرجعية يعاد إنشاؤها والتحقق منها داخل نفس المعاملة، والمشغلات تعود لأوضاعها، والترقيم يعود عند الفشل. لا حذف متسلسل لجداول خارج النطاق.
- بعد النجاح تُغلق الجلسات. حساب الأدمن الذي نفذ الاستعادة، بكل بياناته وPIN الحالي، يظل كما هو؛ يجب أن يكون نفس معرفه موجودًا بالملف. تدخل مجددًا، وتُحمّل هوية النظام المستعادة.
- الجلسات وروابط ربط تيليجرام المؤقتة وطلبات إعادة PIN القديمة لا تُعاد. طلبات إرسال تيليجرام المعلقة لا تُعاد؛ سجلات الإرسال المكتمل/الملغى محفوظة. حسابات تيليجرام وتفضيلات الإرسال التلقائي للـPDF تتوقف وتحتاج مراجعة ثم إعادة تفعيل من إعداداتها. إرسال خرج بالفعل إلى الشبكة قبل الاستعادة لا يمكن سحبه.
- عند فشل تأكيد الاتصال لا توجد إعادة تنفيذ تلقائية. يظهر بعد الدخول «فحص نتيجة الاستعادة»؛ يُحفظ مرجع الطلب ومعرف الأدمن فقط في تخزين الجهاز، دون ملف مفكوك أو كلمة مرور أو مفتاح. المراجعات المكتملة محفوظة بالخادم لتأكيد النتيجة.

## النطاق والحدود

النسخة تعيد جداول `public.tower_*` المتوافقة تمامًا مع بنية القاعدة الحالية، بصيغة النسخ القائمة منSQL263؛ رقم3.5.0داخل الملف هو إصدار صيغة النسخ ويظل مدعومًا. ليست ترقية مخطط أو نقلًا تلقائيًا بين قواعد مختلفة. إعدادات Cloudflare والأسرار والملفات خارج قاعدة البيانات ليست ضمنها. الخادم يستقبل البيانات المفكوكة عبرHTTPS لإجراء المراجعة والتنفيذ، ولا يخزن ملف النسخة أو كلمة مروره في جدول المراجعات.

المراجعة والتنفيذ يقفلان جداول التطبيق مؤقتًا لضمان الاتساق. وجود علاقات واردة من جداول خارج التطبيق أو تقسيم/وراثة جداول أو قيود مرجعية غير معتمدة أو قواعد كتابة خاصة أو تسلسل بزيادة غير1 يوقف الاستعادة قبل اكتمالها ويحتاج مراجعة تقنية. لا يتم تجاوز هذه الحالات بحذف خارج النطاق.

اختُبر التنفيذ والرجوع لنسخة الأمان على قاعدة PostgreSQL محلية مستقلة عبرPGlite ببيانات تجريبية وعلاقات دائرية وقيود فعلية. ليست نسخة من قاعدة الإنتاج، ولا تثبت قبول كل بياناتها أو تجربة واجهتها. لم ينفذ المساعد SQL أو استعادة أو حذفًا على السيستم الأونلاين، ولم ينشرCloudflare أو يرسل إشعارات. التقارير وPDF دون تعديل. التجربة البصرية والموبايل والقبول الأونلاين للمستخدم.
