# إصدار Tower App V3.8.2

إصلاح تنزيل الإصدار الحالي من الإعدادات. **لا SQL جديد؛ ارفع ZIP تشغيل V3.8.2 فقط بالـUpdater، ثم حدّث الصفحة تحديثًا كاملًا Ctrl+F5.**

الزر أصبح رابط تنزيل أصليًا يفتحه المتصفح مباشرة بنفس الصيغة التي أكد المستخدم نجاحها:
`https://github.com/islamsallams/tower-app/raw/main/releases/Vرقم/Tower_App_Vرقم.zip`

رقم الإصدار يأتي من سياق الخادم المحمّل، مع الرجوع لرقم الواجهة عند غيابه. لا ينتظر ضغط الزر استدعاء adminDownloadRuntime350 أو جلب ZIP عبر Cloudflare أو فك Base64. يستطيع المتصفح استخدام جلسة GitHub الخاصة بالمستخدم عند الحاجة، ويفتح الرابط في تبويب منفصل حتى يظل التطبيق مفتوحًا. نجاح فتح الرابط لا يُعرض كإثبات أن حفظ الملف اكتمل.

كان مسار V3.8.1 يحاول جلب الحزمة من الخادم؛ نجاح الرابط عند المستخدم لم يكن يثبت نجاح طلب Cloudflare، وقد أبلغ المستخدم باستمرار CURRENT_RELEASE_ARCHIVE_UNAVAILABLE. الإصلاح هنا يزيل هذه الوساطة من مسار الزر، بدل إضافة إعادة محاولة أخرى لها. السبب التفصيلي لفشل الاتصالات السابقة لم يُثبت من سجل Cloudflare.

المعالج downloadRuntime350 محفوظ لاستدعاءات الواجهة القديمة، ويبدأ نفس التنزيل المباشر دون RPC. واجهات Worker القديمة وصلاحياتها وعقود ردها محفوظة؛ Worker تغير فيه رقم الإصدار فقط. تحميل التشغيل لا يزال ملف كود منشورًا، منفصلًا عن نسخة البيانات المشفّرة وعن إعدادات الاستضافة والأسرار.

نفس هوية الأزرار الحالية، مع رابط أصلي قابل للوحة المفاتيح والقائمة السياقية وتركيز واضح. الجرس وإغلاق المجموعة ونسخ نتائج الفحص والاستعادة والتشفير والتقارير وPDF كما هي. لا تصفير ولا SQL حي ولا استعادة أو حذف أو نشر Cloudflare أو إرسال خارجي. قبول الشاشات والتنزيل من البيئة المنشورة للمستخدم؛ اختبارات الكود لا تثبت ذلك.
