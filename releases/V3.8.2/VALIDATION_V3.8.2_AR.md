# تحقق إصدار V3.8.2

نجحت18 مجموعة فحوص محلية:5 نماذج كود، و6 لحفظ الوظائف والملفات، و7 لتغليف التشغيل بكود Updater V2.3.1 الفعلي. النتائج في qa/v3.8.2 وdelivery-checks.json.

- رابط إعدادات أصلي بلا onclick، بنفس صيغة github.com/raw/main المعتمدة، واسم ملف الإصدار الصحيح، وtarget منفصل وnoopener/noreferrer. يعتمد على إصدار سياق الخادم ويتراجع للواجهة إذا غاب أو كان غير صالح؛ رقم الإصدار محصور في ثلاث مجموعات أرقام، ولا يدخل رمز جلسة أو مدخل حر في الرابط.
- نموذج المعالج المتوافق مع زر الواجهة القديم ينقر رابطًا أصليًا في نفس حدث المستخدم ويحذفه بعده. أدوات النموذج ترمي خطأ لو استُخدم RPC أو fetch أو Blob؛ جميع الحالات نجحت دون أي منها. أدوات التنزيل في القسم لا تظهر لغير الأدمن، ومداخل النسخ والاستعادة محفوظة.
- طابقت86 دالة تقارير/PDF وكل دوال التطبيق السابقة عدا دالتي عرض رابط التشغيل ومعالج التنزيل. Worker مطابق للنسخة السابقة بعد تطبيع رقم الإصدار؛ لا تغيير لعقود API أو الصلاحيات أو SQL أو بيانات الحسابات. ملفات SQL القديمة32 كما هي، وroot/public متطابقان، وملف الربط كما هو. CSS إضافة محددة للرابط الأصلي وتركيزه فقط.
- قبل كود Updater V2.3.1 الفعلي ZIP من5 ملفات، وأنتج public المطابق دون كشف Worker كأصل عام، مع حفظ الكرون والمتغيرات والربط. SOURCE يحفظ كل المسارات والملفات التاريخية؛ لا تغيّر ملفات الاختبارات السابقة أو التقارير أو SQL.

هذه اختبارات كود ببيانات مصطنعة. لا متصفح أو صور شاشة أو اختبار تنزيل من رابط Cloudflare المنشور، ولا SQL حي أو حذف أو استعادة أو إرسال. حالة الربط من Worker ليست محور فحص جديد لأن التنزيل الفعلي أصبح من المتصفح. لم يُثبت سبب فشل الشبكة السابق بتفاصيله؛ الذي ثبته بلاغ المستخدم هو استمرار فشل الوسيط مع نجاح الرابط المباشر عنده. تجربة الزر بعد نشر الإصدار وتحديث الصفحة للمستخدم.
