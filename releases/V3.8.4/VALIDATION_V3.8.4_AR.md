# تحقق إصدار V3.8.4

نجحت37 مجموعة محلية:9 Worker، و14 نماذج واجهة وService Worker، و1 على workerd الحقيقي محليًا، و6 حفظ نطاق، و7 توافق Updater V2.3.1.

اختبرنا الاستثناء في كل مرحلة على حدة، بما فيها انتهاء المهلة، وتحققنا من تخزين الرمز الصحيح ومن عدم تضمين السجل لمفاتيح أو endpoint أو نص الرسالة أو الاستثناء. بقيت حالات HTTP201/410/429/503/403 وعزل المستلم والتشفير وفكّه مستقلًا صحيحة في النموذج المحلي. تُعرض حالة الخادم في البطاقة، مع تمييز قبول المزوّد عن وصول الجهاز وإظهار أن السجل القديم بلا سبب مفصّل.

اختبار workerd المحلي استخدم أحدث تاريخ توافق يدعمه المحرك المثبت2026-08-06، بينما تاريخ الإنتاج2026-10-09 محفوظ في wrangler.toml دون تعديل. نجح توليد المفتاح وتصديره واستعادته بعد JSON، وتجهيز الرسالة والتوقيع وواجهة المهلة. هذا ليس اختبار بيئة الإنتاج أو الجهاز؛ لا نعتبره نفيًا لكل أسباب العطل الفعلي.

كل33ملف SQL قديم محفوظ بالبايت ولا SQL جديد. كل86دالة تقرير/PDF في التطبيق محفوظة، ودوال Worker القديمة دون تغيير عدا تشخيص محاولة Push وثابت الإصدار. السكربت الخاص بالمتصفح وCSS والربط ومحرك المشاوير ومهله وصلاحياته دون تغيير. SOURCE يحتفظ بكل مسارات وبايتاتV3.8.3 باستثناء runtime/public وAGENTS المحدثة صراحة، مع ملفات الدفعة الجديدة.

لا اختبار متصفح أو صور أو إرسال Push/Telegram فعلي أو SQL حي أو نشر Cloudflare. السبب الفعلي لـPENDING/0 لم يتحدد؛ ننتظر النتيجة الجديدة من المستخدم. لا إغلاق لبند وصول إشعارات الخلفية بهذه الفحوص، ولا تغيير للتصفير أو التشفير أو الاستعادة.
