# إصدار V3.8.7 — فحص صوت الجهاز وملف تين تان

أفاد المستخدم بوصول كل إشعار للموبايل بصوت بعد تعطيل إشعارات الأمين على الكمبيوتر. نسجل نجاح هذا الاختبار وارتباط النتيجة بتفعيل الكمبيوتر، ولا نستنتج منه أن الكمبيوتر يستهلك الإرسال أو أن سبب الصمت تحدد.

أضيف سطر «آخر استقبال محلي» داخل إعدادات التنبيهات المقفولة افتراضيًا. يسجل وقت آخر استقبال على المتصفح الحالي وهل التطبيق طلب صوت النظام، أو طلب الصمت لوجود صفحة نفس الحساب ظاهرة على نفس الجهاز. يوضح أيضًا هل قبل المتصفح طلب العرض؛ هذا لا يثبت أن المستخدم سمع الصوت أو شاهد الإشعار فعليًا.

السجل محلي على الجهاز، ومقصور على الحساب المطابق، ويحفظ آخر نتيجة فقط. لا يتضمن عنوان الإشعار أو نصه أو اسم الساكن أو مبالغ أو مفاتيح أو endpoint أو جلسة، ولا يرسل بيانات استقبال جديدة للخادم. قرار الصوت نفسه لم يتغير: الصفحة المطابقة الظاهرة تجعل إشعار النظام صامتًا لتجنب صوتين، والخلفية تطلب صوت النظام. جهاز الكمبيوتر لا يدخل ضمن صفحات الموبايل في هذا القرار.

أرفقنا Tower_Notification_Ding_Dong.wav، نسخة PCM من نفس ترددات وتوقيت وغلاف جرس الصفحة، لا تسجيلًا على جهاز. تخصيص صوت إشعارات الخلفية يحدده Android والمتصفح، وليس صفحة الويب. لو خيار الصوت متاح لقناة إشعارات الموقع، يختار المستخدم ملف الجرس يدويًا؛ التطبيق لا يستطيع فرض نغمة خاصة عبر Web Push ولا تجاوز الصامت أو عدم الإزعاج.

لا SQL جديد. ارفع ZIP V3.8.7 وحدّث الصفحة بالكامل. افتح إعدادات التنبيهات مرة لتحديث Service Worker القائم ثم أعد فتح الصفحة قبل تجربة جديدة. فعّل إشعارات الكمبيوتر مجددًا للاختبار، واستقبل مشوارًا والموبايل مطفي الشاشة دون فتح المشوار على الكمبيوتر. لو وصل صامتًا، حدّث حالة الجهاز على الموبايل وابعت «آخر استقبال محلي» ووقته.

هذه دفعة تشخيص وتوفير ملف صوت، وليست ادعاء إصلاح سبب الصمت النهائي. لا تغيير للمشاوير أو ثوابتها أو صيغة V3.8.6 أو الحسابات أو التقارير وPDF أو التشفير والاستعادة. لم نرسل إشعارات فعلية أو ننشر Cloudflare أو نشغّل SQL حيًا أو متصفحًا أو صوتًا على سماعة.
