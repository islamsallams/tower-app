# تحقق396

- اختبار يشغّل الدوال الفعلية bootApp وsubmitLogin وenterApp مع مقدمة const KEY/const URL تجريبية مطابقة لطريقة الرفع: يعيد إنتاج TypeError في خطاف395 الأصلي ثم يثبت نجاح التصحيح مع جلسة موجودة ودخول جديد، ومع مقدمة إعدادات أو بدونها.
- اختبار تشخيص يثبت أن فشل بدء الواجهة بعد نجاح الدخول ينسخ مرحلة بدء التطبيق ونوع TypeError وسبب URL is not a constructor، دون PIN أو token. روابطTelegram المصرح بها تمر إلى الصلاحيات القائمة، وروابط حساب آخر لا تفتح.
- مقارنة المصدر395: تغيرت أربعة مواضع بدء/تشخيص فقط مع إضافة مساعد التشخيص؛ خطافTelegram يتغير في تأهيل منشئURLفقط. كلSQLوCSSوالوظائف الأخرى وملفاتAndroidالمصدرية كما هي؛ Worker تغير رقم الإصدار وبياناتAPKفقط.
- فحوص Worker ونموذج النوافذ والتمويل والعداد المعتمدة في395 أعيدت بعد التصحيح ونجحت. بوابة396 تعمل بالتوازي وتنتهي محليًا في أقل من ثانية؛ لا إعادة لفحوصSQLالتي لم تتغير بايتاتها.
- بناءAndroidوفحصLintوشهادةالتوقيع والAPKوسياسته ونموذجالربط، وفحصCRCوتطابقالحزمومصدرهاوبصماتالتسليم.

لا نشرCloudflare أوSQLحي أو دخول حقيقي أو متصفح أو اختبار هاتف أو إرسال رسالة. الاختبار نموذج DOM/حالة يشغّل الكود الحالي، ولا نزعم اختبار الواجهة بصريًا أو مطابقة كل إعدادات الإنتاج. فحص الموقع العام HTTP كان للقراءة فقط ودون حسابات.
